# Baseline 文档更新操作规则

> 来源：pm-conventions §3.3

所有涉及更新 Baseline 的 PM skill 必须遵循：

**更新操作步骤**：
1. 在确认结论内容区域直接修改（新增/修改/删除规则）
2. 同步更新"需求文档位置映射"表的前三列，**不可修改"需求文档位置"列**
3. 在"版本记录"中新增一行
4. 将本次更新详情 Write 到 `变更记录/baseline-vX.md`（X 取版本记录表中最新版本号），不追加到 Baseline 文档内
5. 严格忽略"版本记录"和"更新记录"中的已有内容

**更新详情文件格式**（`变更记录/baseline-vX.md`）：

```markdown
# Baseline vX 更新详情（{日期}）

| 编号 | 更新点 | 变更类型 | 变更前 | 变更后 |
|------|--------|---------|-------|-------|
| C-XX | {事项} | 新增/修改/删除 | {变更前内容，新增时为"—"} | {变更后内容，删除时为"—"} |
```

**改写约束**：仅在用户明确要求"修改 Baseline"/"更新 Baseline"环节可改写；其余环节以 Baseline 为判断基准，不可改写。

**Baseline 局部修复**（适用于 pm-prd-review）：
- 仅涉及 1-2 条确认点 → 在当前 skill 内直接修改
- 涉及 3 条及以上 → 新建场景回退到 `pm-baseline-gen` 完整执行；迭代场景回退到 `pm-prd-update` 更新 Baseline
- 单次执行期间回退累计不超过 2 次

> **"单次执行"定义**：指一次 skill 触发到流程终止（pm-conventions §11.1）的完整生命周期。Phase 2 修复循环不重置计数。
