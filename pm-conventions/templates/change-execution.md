# 变更执行清单与自检规范

> [适用范围] 本文件仅适用于 pm-prd-update、pm-proto-gen Phase 3。pm-baseline、pm-prd-draft、pm-prd-review 无需加载。

## 1. 变更执行清单生成

修改需求文档前，必须先生成变更执行清单：

| # | 修改点 | 目标位置 | 修改类型 | 状态 |
|---|--------|---------|---------|------|
| 1 | {修改点} | {章节+行号} | 新增/修改/删除 | ⬜ |

## 2. 连带影响扫描

清单生成后，结合需求文档和 Baseline 位置映射表，扫描连带影响：

1. 读取变更执行清单中的修改点
2. 读取 Baseline 的"需求文档位置映射"表
3. 对每个修改点，查找 Baseline 中所有映射到相同章节/相邻章节的确认点
4. 检查这些确认点对应的文档位置是否也需要连带更新
5. 额外检查以下连带位置：

| 修改类型 | 必须检查的连带位置 |
|---------|-------------------|
| 功能描述变更 | 功能概述 > 功能清单表格对应行的"说明"列和"使用人及使用场景"列 |
| 约束/规则变更 | 对应功能的流程图判断节点、时序图消息 |
| 枚举值/状态变更 | 需求详情中引用该枚举值的其他功能描述 |
| 交互流程变更 | 整体业务流程图（如有）及各模块内部流程图 |
| 任何正文变更 | 待确认项中引用该功能的条目 |

6. 将发现的连带影响补充到清单中，补充后的完整清单交给用户确认

## 3. 大文档增量更新策略

| 文档行数 | 更新策略 | 说明 |
|---------|---------|------|
| ≤300 行 | 全量重写 | 文档短，全量重写最安全 |
| 300-1000 行 | 分段更新 | 仅重写受影响的章节，未受影响章节保持原样 |
| >1000 行 | 精确增量更新 | 按变更执行清单逐点修改，使用 Edit 工具精确定位和替换 |

**流程图/时序图专项检查**：当变更涉及业务逻辑、流程、状态变化时，必须扫描文档中所有 Mermaid 代码块，对比变更内容与每个图的节点，识别哪些图需要更新，将"更新 XX 流程图/时序图"作为独立的清单项列出。

## 4. 更新内容确认规则（批量+异议模式）

在确定更新策略后、执行修改前，按受影响的模块/功能批量输出更新内容供用户确认。

### 执行方式

1. 根据变更执行清单，按目标章节/模块将修改点分组
2. **一次性输出所有分组的更新内容**（含变更前后对比），每组格式如下：

```
📝 **模块 X/N：{模块名称}**（对应清单 #{清单编号}）

**变更前：**
> {原文内容摘要或完整原文}

**变更后：**
> {修改后的完整内容}

**变更说明：** {简述修改原因和内容}
```

3. 询问用户："以上 N 个模块的更新内容，如有异议请指出具体模块编号和调整意见，无异议回复'确认'即可。"
4. 用户回复"确认"→ 全部通过，统一执行文档修改
5. 用户指出某模块需调整 → 仅修改该模块后再次确认该模块，其余模块视为已确认
6. 所有模块确认后，将确认结果写入 sessions 目录（按 §5 规范）

### 分组与合并规则

按目标章节/模块分组，连带影响归入触发修改所在组。AI 可根据修改点数量和关联性建议合并确认，但需用户同意。

### 禁止事项

- 禁止跳过确认，直接执行修改
- 禁止在用户未确认的情况下先写入文件
- 禁止将未展示的连带影响修改静默执行

## 5. 更新确认落盘规范

更新过程中的模块确认结果必须持续写入 sessions 目录，避免长对话中内容漂移。

### sessions 目录

路径：`sessions/{request_id}/`，request_id 格式 `{skill缩写}_{YYYYMMDD}_{HHmmss}`（draft/update/proto/test）。

- `update_change_list.json` — 分组后的变更执行清单，清单确认后写入
- `update_confirmed_sections.json` — 用户已确认的最终更新内容，每模块确认后写入
- `update_confirmation_log.md` — "原内容→修改意见→确认内容"过程记录，每轮确认后写入

### 中断恢复

skill 执行前扫描到 sessions 目录下存在未完成的更新确认文件时，向用户展示已确认和未确认的模块列表，提供"继续/重新开始"选择。

## 6. AI 自检

执行完所有修改后，AI 必须进行自检：

1. 重新读取修改后的文档（从文件路径读取，不使用内存版本）
2. 逐条回查清单中的每个修改点，确认内容是否已正确更新
3. 检查结构完整性：章节编号连续、功能编号连续、YAML frontmatter version 已更新、版本记录和更新记录已补充
4. 检查格式一致性：Mermaid 代码块完整、表格格式正确、编号层级正确
5. 如自检发现遗漏，自动补充修改。自检最多执行 1 次，不循环
6. 输出执行结果对照表：

| # | 修改点 | 目标位置 | 执行状态 | 验证说明 |
|---|--------|---------|---------|---------|
| 1 | {修改点} | {位置} | ✅ 已完成 / ⚠️ 需确认 | {说明} |

总计：X 项中 Y 项已完成，Z 项需人工确认
