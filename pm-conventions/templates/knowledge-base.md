## 10. 知识库路径约定

### 10.1 知识库路径

所有 PM skill 统一使用：`~/Developer/Projects/`

该目录下包含多个知识库子目录，每个子目录覆盖不同的业务域：

| 子目录 | 覆盖范围 |
|---|---|
| `ai-knowledge/` | 知识库运营平台（knowledge、knowledge-faq、assist_sop_console、assist.kf.sop.server、xybot-adapter、sop_function） |
| `xkf/` | 客服工单系统相关 |
| `xkf-xinde/` | 信德相关 |

AI 在分析需求时，应根据需求涉及的业务域，到对应子目录下查找相关信息。所有子目录下的内容均属于知识库覆盖范围。

### 10.2 读取策略

| 需要了解的信息 | 读取路径 |
|---|---|
| 项目全貌、角色体系、系统边界 | 对应子目录下的 `project-overview.md` 或 `README.md` |
| 服务间依赖、联动关系 | 对应子目录下的 `project-map.md`、`architecture-overview.md` |
| 某服务的业务逻辑和数据结构 | `{子目录}/{service}/docs/business-domains.md`、`database-schema.md` |
| 枚举值、常量定义 | `{子目录}/{service}/docs/enums-and-constants.md` |
| 前端菜单和页面结构 | `{子目录}/{前端服务}/docs/menu-tree.md`、`page-modules.md` |
| 现有 API 接口 | `{子目录}/{service}/docs/api-docs.md` |

AI 根据需求涉及的业务域和服务，先定位到正确的子目录，再按需读取对应服务目录下的文档，无需全部读取。

### 10.3 使用约束

知识库信息仅用于理解"系统现状"。PRD 和 Baseline 中禁止出现代码级细节（类名、方法名等）。

**例外**：
- Baseline 数据指标章节（§5.3）中的表名和关键字段名属于"数据同步需求描述"，允许出现，因为数据同步需精确到表/字段粒度才能执行。
- 保存的【知识上下文文件】中可以包括所有获取的代码级细节信息；

### 10.4 知识上下文文件

需求目录下如存在 `{需求简称}-知识上下文.md`，在需要读取知识库时**优先读此文件**。

| 场景 | 行为 |
|------|------|
| 知识上下文文件存在，信息满足当前步骤需要 | 不再读知识库原文件 |
| 知识上下文文件存在，信息不足 | 按 §10.2 原有规则补读知识库原文件 |
| 知识上下文文件不存在 | 按 §10.2 原有规则正常读取知识库 |

**文件性质**：知识上下文文件是本需求相关知识库信息的**摘要副本**，不是缓存。后续 skill 在执行过程中如果从知识库获取了该文件中未覆盖的新信息，应追加到该文件中。

**"信息不足"判断规则**：
默认信任知识上下文文件。仅以下条件成立时，视为信息不足，需按 §10.2 补读知识库：
- 当前步骤涉及的服务名称在知识上下文文件中**完全没有对应章节**（章节存在但内容不够详细不算不足）
- 需要验证**具体枚举值、字段类型、接口参数**等精确数据，且知识上下文文件的对应章节中未列出这些具体数值
- 知识上下文文件不包含当前步骤涉及的前端页面信息（如涉及前端）
- **当前步骤需要描述某个数据表的完整结构（如PRD中需列出该表所有字段），但知识上下文中该表仅列出了部分字段**

**知识上下文体积控制规则**（配合 pm-baseline-gen 补全标准）：
- 枚举值超过 20 个时：优先按需求涉及的分组完整列出该分组值；如无明确分组，列出需求涉及值 + 总数说明
- 关联表（仅查询引用）：仅记录主键 + 需求涉及字段，不记录完整字段列表

> **设计原则**：知识上下文文件经 pm-baseline-gen 功能架构补全改造后，对需求涉及的模块已提供模块级完整信息。因此"章节存在但不够详细"的情况大幅减少。新增的判断条件仅覆盖改造遗漏的边界场景，不改变"默认信任"的基本原则。

> **设计原则**：默认信任知识上下文文件已有的信息，仅在需要精确数值验证或明确缺少对应章节时才触发补读。避免因"不确定是否充足"而频繁回退到全量读取知识库，否则知识上下文文件的节省效果将大打折扣。

**过时预警规则**：
- 如果知识上下文文件的"最后更新"时间早于 Baseline 文档最新版本记录的日期，在 AI 读取时输出一行提示：`⚠️ 知识上下文文件可能已过时（最后更新: {日期}，Baseline 最新版本: {日期}），如涉及新增模块请注意验证`
- 提示后仍优先使用知识上下文文件，不自动触发补读

**回写规则**：
- 以下 skill 有权写入知识上下文文件：
  - pm-baseline-gen：首次生成，以及按功能架构补全
  - pm-prd-draft：L2 验证过程中发现的新信息回写
  - pm-prd-update：Baseline 更新时的同步检查（仅新增模块触发补读时）
- 其他 skill 暂不回写
- 回写前先搜索知识上下文文件中是否已包含相同信息（关键词匹配），避免重复追加
- 回写内容必须是**知识库原文摘录或直接验证结论**，不可写入 AI 的推断性分析
- 追加到对应章节末尾，标注来源 skill 和日期
- 如目标章节不存在，追加到文件末尾的「七、补充信息」通用章节
- 不修改已有内容
