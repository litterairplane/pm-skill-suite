## 运行模式检测

本 skill 支持两种运行模式，通过 prompt 中的标记判断：

| 模式 | 检测方式 | 确认点行为 |
|------|---------|-----------|
| 非交互模式 | prompt 中包含 `[NON_INTERACTIVE]` 标记 | **所有确认检查点自动跳过**，直接执行后续步骤，最终产出物正常生成 |
| 交互模式 | prompt 中不包含 `[NON_INTERACTIVE]` 标记 | 按 agent.json 中 confirmations 配置的 mode 执行：`auto_pass`=自动通过，`user`=根据 agent.json 确认点模式执行 |

**非交互模式下的特殊处理**：
- 文件定位自动完成
- 映射结果自动确认，直接写入 Baseline
- 映射完整性报告正常输出

---

## Purpose

Baseline 文档作为核心规则基线，需要与需求文档保持位置映射关系。每次需求文档更新后，Baseline 中各确认点对应的需求文档位置可能发生变化，需要重新映射。

本 skill 支持单独触发执行，也可被 pm-prd-review、pm-proto-gen 在其流程中调用。

**映射策略**：无论修改级别，均执行全量位置映射（增量映射会因行号漂移导致失准）。

## 运行建议

本 skill 推荐使用 Sonnet 模型执行。交互模式下使用 `claude --model sonnet` 启动会话。

## 输入

- **Baseline 文档**（必须）：Baseline 文件路径
- **需求文档**（必须）：需求文件路径

## 状态检查

执行前检查 Baseline 位置映射表状态：

| 状态 | 行为 |
|------|------|
| 全部为"—" | 首次映射，从 Step 1 开始 |
| 部分填充 | 交互模式：提供"全量重新映射/继续"选择；非交互模式：默认执行全量重新映射 |
| 全部已填充 | 重新映射（文档更新后） |

> 作为组件被其他 skill 调用时，默认执行全量重新映射，无需额外确认。

## 执行流程

### Step 1：读取文档

> 所有文件必须从路径重新读取，不使用会话缓存。详见 pm-conventions §5。

从用户提供的路径重新读取 Baseline 和需求文档。自动推断需求名称；如无法推断，主动询问。

### Step 2：执行位置映射

比对 Baseline 与需求文档，找到每个确认点在需求文档中的**具体位置**。

#### 核心约束

- **仅更新"需求文档位置"列**，不可改写前三列和确认结论内容区域
- **严格忽略"版本记录"区域**
- **完全穷举**：穷尽每条确认结论在需求文档中的所有映射位置（正文+流程图+时序图+交互说明等）

#### 映射范围（穷举清单）

映射时必须逐一检查需求文档中以下区域：

| 区域 | 检查内容 |
|------|---------|
| 需求背景 | 当前问题、需求价值、预期效果（如存在） |
| 功能清单 | 功能名称、一句话说明、使用人及使用场景（如存在） |
| 整体业务流程（如存在） | 全局流程图节点、系统间时序图 |
| 需求详情正文 | 各模块中的功能描述、约束条件、错误处理 |
| 交互说明 | 页面布局、操作步骤、弹窗文案、按钮状态、错误提示 |
| 流程图 | 节点文字、判断分支条件、异常路径 |
| 时序图 | 参与者、消息、alt/loop 分支 |
| 待确认项 | 各 Q-xx 在正文中的引用位置 |
| 版本记录/更新记录 | 版本号、变更概述 |

#### 映射格式

位置格式：`{章节编号} {功能编号} {具体位置}（第{行号}行）`，多个位置用中文分号 `；` 分隔。

示例：`三、3.1 开票申请 约束第1条（第125行）；三、3.1 流程图起始节点（第140行）`

### Step 3：映射完整性自检

汇总映射完整性报告（完全匹配 / 未找到对应 / 多位置引用的条数）。未找到对应的规则需重点告知用户，可能是需求文档遗漏或 Baseline 规则过时。

### Step 3.5：更新版本记录

映射完成后：
1. 在版本记录中新增一行（如"基于需求定稿 vX 重新映射全部位置"）。如本次变更中已记录过版本，合并到同一版本
2. 将本次映射更新详情 Write 到 `变更记录/baseline-vX.md`（遵循 pm-conventions §3.3）

### Step 4：输出

- 更新后的 Baseline 文档原地保存
- 输出文件绝对路径 + 映射完整性报告 + 映射覆盖情况
