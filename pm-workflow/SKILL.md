## 运行模式检测

本 skill 支持两种运行模式，通过 prompt 中的标记判断：

| 模式 | 检测方式 | 确认点行为 |
|------|---------|-----------|
| 非交互模式 | prompt 中包含 `[NON_INTERACTIVE]` 标记 | 自动扫描并输出进度总览，无需用户确认 |
| 交互模式 | prompt 中不包含 `[NON_INTERACTIVE]` 标记 | 按 agent.json 中 confirmations 配置的 mode 执行 |

**注意**：pm-workflow 为只读导航 skill，无产出物，两种模式下行为基本一致。非交互模式下多匹配时自动选择第一个匹配项。

---

## Purpose

需求工作流的"导航仪"——通过扫描需求目录下的产物文件，判断每个需求的当前进度，
展示进度总览，并给出下一步应调用的 skill 和可直接复制的调用命令。

**定位**：只做导航，不做执行。不读文件内容（除极少数判断场景），不生成任何文档，不修改任何文件。

## 硬性边界

- 不执行任何 PM skill 的实际工作
- 不生成文档、不做多轮确认
- 不修改任何文件
- 扫描范围限定在 pm-conventions §2 定义的产品需求目录（`~/Developer/my-project/产品需求/`）
- 扫描时只看文件名和目录结构，不读取文件内容
- 输出的调用命令必须符合对应 skill 的触发词规范
- 执行完毕后不输出会话切换引导

## 三种使用模式

### 模式 1：全局总览

**触发**：`/pm-workflow`（不带参数）

**行为**：
1. 扫描 `~/Developer/my-project/产品需求/` 下所有需求目录
2. 排除非需求目录（`0 操作指引`、`0 其他`、`0 业务分析` 等以 `0` 开头的目录）
3. 对每个需求目录执行状态检测（见 §状态检测逻辑）
4. 按最后更新时间倒序输出总览表

**输出格式**：

```markdown
📋 需求进度总览（共 {N} 个需求）

| 需求 | 当前阶段 | 最新产物 | 最后更新 |
|------|---------|---------|---------|
| {需求目录名} | {阶段描述} | {最新文件名} | {日期} |
| ... | ... | ... | ... |
```

### 模式 2：单需求进度

**触发**：`/pm-workflow {需求名}`

**行为**：
1. 模糊匹配需求目录名：目录名包含用户输入的关键词即匹配（如输入"排班"匹配"V42-投诉工单排班派单优化"）
2. 无匹配时提示"未找到包含'{关键词}'的需求目录"并列出所有可用需求目录
3. 多个匹配时：交互模式列出候选让用户选择；非交互模式自动选择第一个匹配项
4. 对匹配的需求目录执行详细状态检测
5. 输出环节级进度和下一步引导

**输出格式**：

```markdown
📋 「{需求名}」进度

{环节1状态图标} {环节名}    → {状态描述}
{环节2状态图标} {环节名}    → {状态描述}
...

📌 建议下一步：{下一步描述}

👇 复制以下命令到新会话执行：
{具体调用命令}
```

**状态图标**：
- `✅` 已完成
- `🔶` 进行中（有中间产物但未完成）
- `⬜` 未执行

### 模式 3：跳转指定环节

**触发**：`/pm-workflow {需求名} {目标环节}`

目标环节关键词映射：

| 用户输入 | 目标 skill |
|---------|-----------|
| 分析、需求分析 | pm-req-analysis |
| baseline、基线 | pm-baseline-gen |
| 原型、proto | pm-proto-gen |
| 评审原型、交互评审 | pm-proto-review |
| 写PRD、初稿、需求文档 | pm-prd-draft |
| 评审、review | pm-prd-review |
| 改需求、更新、变更 | pm-prd-update |
| 操作指引 | pm-operation-guide |

**行为**：
1. 匹配需求目录
2. 检查目标环节的前置条件是否满足
3. 满足 → 输出调用命令
4. 不满足 → 说明缺少什么，建议先执行哪个环节

## 状态检测逻辑

### 扫描规则

对需求目录执行以下检测（仅扫描文件名和目录结构，不读文件内容）：

> **术语说明**：下表中 `{简称}` 指"需求简称"，`{标题}` 指"需求标题"，定义见 pm-conventions §6.5。
> **判断标准**："无某产物"指对应目录不存在 OR 目录存在但下无匹配文件模式的文件。

| 序号 | 环节 | 检测方法 | 产物文件模式 |
|------|------|---------|-------------|
| 1 | 需求分析 | 根目录存在 `*-需求分析-v*.md` | `{简称}-需求分析-v{N}.md` |
| 2 | Baseline | 根目录存在 `*-Baseline.md` | `{简称}-Baseline.md` |
| 3 | 探索性原型 | `原型/` 下存在 `.html` 文件，且无需求文档 | `原型/*.html` |
| 4 | 交互评审 | `变更记录/` 下存在文件（Baseline 有过更新） | `变更记录/baseline-v*.md` |
| 5 | 需求文档 | `需求文档/` 下存在 `*-需求文档-v*.md` | `{简称}-需求文档-v{N}.md` |
| 6 | 需求评审 | `评审报告/` 下存在 `*-需求评审报告.md` | `{标题}-v{N}-需求评审报告.md` |
| 7 | 精确原型 | `原型/` 下存在 `.html` 文件，且已有需求文档 | `原型/*.html` |
| 8 | 操作指引 | `操作指引/` 下存在 `.md` 文件 | `操作指引/{名称}.md` |

### 补充检测（仅在单需求进度模式下执行）

- **知识上下文文件**：根目录存在 `*-知识上下文.md`（仅展示有/无，不影响进度判断）
- **Baseline 变更次数**：统计 `变更记录/baseline-v*.md` 的文件数量
- **需求文档版本**：取 `需求文档/` 下最大版本号
- **评审报告版本**：取 `评审报告/` 下最大版本号
- **修改建议**：统计 `修改建议/` 下的文件数量

### 特殊场景处理

**需求目录为空**：需求目录存在但无任何产物文件时，显示"未开始"状态，所有环节标记 `⬜`。

**通用跳过规则**：如果某环节的产物不存在，但后续环节的产物已存在，该环节标记为"跳过"（如无分析报告但有 Baseline → 需求分析标记为"跳过"）。

**无分析报告但有 Baseline**：属于通用跳过规则的典型场景，部分早期需求跳过了 pm-req-analysis 直接创建 Baseline。

**原型的探索/精确判断**：
- 有原型 + 无需求文档 → 判定为探索性原型
- 有原型 + 有需求文档 → 判定为精确原型（或探索性原型已升级）

**原始需求文件**：部分需求目录下存在 `原始需求.md`，这是用户手动放入的原始资料，不属于任何 skill 的产物，扫描时忽略。

## 进度推断与下一步建议

根据已有产物组合，推断当前阶段和建议下一步：

| 已有产物 | 当前阶段判定 | 建议下一步 | 调用命令 |
|---------|------------|-----------|---------|
| 无任何产物 | 未开始 | 需求分析 | `/pm-req-analysis {需求描述}` |
| 仅有分析报告 | 需求分析已完成 | 生成 Baseline | `/pm-baseline-gen {需求名}` |
| 有 Baseline，无原型无 PRD | Baseline 已完成 | 生成探索性原型 或 写 PRD | `/pm-proto-gen {需求名}` 或 `/pm-prd-draft {需求名}` |
| 有 Baseline + 原型，无 PRD | 探索性原型已完成 | 交互评审 | `/pm-proto-review {需求名}` |
| 有 Baseline + PRD，无评审报告 | 需求文档已完成 | 需求评审 | `/pm-prd-review {需求名}` |
| 有 PRD + 评审报告 | 需求评审已完成 | 查看评审结果决定下一步 | 有修改需要：`/pm-prd-update {需求名}`；无修改需要：`/pm-proto-gen {需求名}` 或 `/pm-operation-guide {需求名}` |
| 有 PRD + 评审报告 + 修改建议 | 修改建议已生成 | 执行需求变更 | `/pm-prd-update {需求名}` |
| 有 PRD + 评审通过 + 精确原型 | 精确原型已完成 | 操作指引 | `/pm-operation-guide {需求名}` |
| 有操作指引 | 全流程已完成 | 无 | — |

**多选项场景的处理**：当建议下一步有多个选项时（如"生成原型 或 写 PRD"），输出两个选项并标注适用条件：

```markdown
📌 建议下一步（二选一）：

**涉及前端页面** → 先生成探索性原型：
/pm-proto-gen {需求名}

**不涉及前端页面** → 直接写需求文档：
/pm-prd-draft {需求名}
```

## 前置条件检查（模式 3 跳转时使用）

| 目标环节 | 前置条件 |
|---------|---------|
| pm-req-analysis | 无 |
| pm-baseline-gen | 建议有分析报告（非必须） |
| pm-proto-gen（探索性） | 需要 Baseline |
| pm-proto-gen（精确） | 需要 PRD |
| pm-proto-review | 需要 Baseline + 原型 |
| pm-prd-draft | 需要 Baseline |
| pm-prd-review | 需要 Baseline + PRD |
| pm-prd-update | 需要 PRD |
| pm-operation-guide | 需要 PRD |

前置条件不满足时，输出：

```markdown
⚠️ 前置条件不满足

执行 /pm-prd-draft 需要 Baseline 文档，但当前需求目录下未找到。

建议先执行：
/pm-baseline-gen {需求名}
```
