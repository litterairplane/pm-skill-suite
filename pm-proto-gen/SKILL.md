## 运行模式检测

本 skill 支持两种运行模式，通过 prompt 中的标记判断：

| 模式 | 检测方式 | 确认点行为 |
|------|---------|-----------|
| 非交互模式 | prompt 中包含 `[NON_INTERACTIVE]` 标记 | **所有确认检查点自动跳过**，直接执行后续步骤，最终产出物正常生成 |
| 交互模式 | prompt 中不包含 `[NON_INTERACTIVE]` 标记 | 按 agent.json 中 confirmations 配置的 mode 执行：`auto_pass`=自动通过，`user`=根据 agent.json 确认点模式执行 |

**非交互模式下的特殊处理**：
- 自动判断执行状态和输入模式，直接进入原型生成
- 页面列表自动确认，直接生成
- 原型正常生成，在 Banner 中标注"非交互模式生成"

## Purpose

基于 Baseline 或 PRD 生成 B 端 HTML 原型。支持两种输入模式：

- **Baseline 模式（探索性原型）**：在 PRD 之前，基于 Baseline 快速生成原型，用于交互方案验证
- **PRD 模式（精确原型）**：基于 PRD 生成与需求严格对齐的原型，用于开发参考

> 推荐模型：Sonnet（原型生成为样式密集型任务，Sonnet 足以胜任，可节省约 40-60% 的 token 成本）

## Scope 边界

### In Scope
- 基于 Baseline 或 PRD 生成 PC 端 B 端 HTML 原型（1920x1080 设计，最小适配 1366px）
- 存量页面改造（基于已有 Vue 代码还原并叠加新功能）
- 纯 HTML/CSS/JS，离线可用，不依赖任何外部框架或 CDN

### Out of Scope
- 移动端适配、真实前端逻辑、真实图表渲染、设计系统输出、可用性测试
- 交互评审（由 pm-proto-review 负责）
- 需求文档更新（由 pm-prd-update 负责）

## 双输入模式

```
输入模式判断逻辑：
├── 有 PRD → PRD 模式（精确原型）
└── 无 PRD → Baseline 模式（探索性原型）
```

> **设计说明**：Baseline 在 PRD 生成前必然已存在，"两者都有"是常态而非例外。因此以 PRD 的存在性作为唯一分支条件，Baseline 作为默认可用输入不参与模式判断。

| | Baseline 模式（探索性原型） | PRD 模式（精确原型） |
|---|---|---|
| 输入 | Baseline + 知识库 | PRD + Baseline(可选) + 知识库 |
| 原型精度 | ~80%（布局正确、核心流程完整） | ~95%（字段、规则、状态完全对齐） |
| 适用阶段 | PRD 前的交互探索 | PRD 后的精确原型 |
| 页面信息来源 | Baseline 功能架构树 + 核心规则 | PRD 需求详情 + 数据模型 |
| 字段完整度 | 核心字段完整，辅助字段可能缺失 | 全部字段对齐 PRD |
| 交互说明 | 基于 Baseline 规则推断 | 严格按 PRD 交互说明 |

### Baseline 模式的页面信息提取规则

从 Baseline 提取原型生成所需信息的映射关系：

| 原型所需信息 | Baseline 提取位置 | 备注 |
|------------|------------------|------|
| 页面/功能清单 | `三、功能架构` → 功能架构树 | 业务场景层的每个功能 → 一个页面或弹窗 |
| 字段列表 | `五、模块核心规则` → 各功能的确认结论 | 提取结论中提到的字段名和类型 |
| 业务规则 | `五、模块核心规则` → 确认结论 | 提取条件判断、状态流转、权限控制 |
| 页面布局 | `五、模块核心规则` + 知识库 page-modules.md | 参考现有系统页面布局 |
| 数据模型 | `五、模块核心规则` + 知识库 database-schema.md | 字段类型、枚举值 |
| 角色权限 | `五、模块核心规则` → 权限相关确认结论 | 影响页面元素可见性 |

### Baseline 模式的特殊处理

1. **核心/辅助字段判定**：Baseline 确认结论中明确提到的字段 = 核心字段，必须出现在原型中；知识库补充的字段 = 辅助字段，可用 TBD 标记
2. **字段缺失容忍**：辅助字段从知识库 `database-schema.md` 补充；仍不确定的标记 `TBD` 但不阻塞生成
3. **交互推断**：无明确交互说明时，按页面类型模板的默认交互规则生成
4. **原型 Banner 标记**：探索性原型在 Banner 区域添加以下固定标记和文案：
   ```html
   <!-- proto-banner: exploratory -->
   探索性原型 — 基于 Baseline 生成，待交互评审后完善
   ```
   PRD 模式对应标记为：
   ```html
   <!-- proto-banner: precise -->
   精确原型 — 基于 PRD v{N} 生成
   ```
   > HTML 注释标记为程序化判定使用，文案为用户可见提示，两者必须同时存在。

## Phase 1：生成原型

> [必须] 从文件路径读取所有输入文件，详见 pm-conventions §5。

### Step 1：分析输入文档 + 前端代码

`[Phase 1 · Step 1/4]`

**基底定位（前置）**：按 `templates/generation-rules.md` 的"基底定位步骤"执行——判断需求所属系统 → 读 `~/Developer/my-project/原型基底/{系统}/index.md` → 按需求功能匹配页面 → 对每个页面按快照是否存在选择优先级 0/2/3 路径。匹配结果与生成方式在后续 Step 中遵循。

**Baseline 模式**：
1. 读取 Baseline 文档，按"页面信息提取规则"提取功能清单、字段、规则
2. **读取知识上下文文件**（如存在，按 pm-conventions §10.4）
3. 如知识上下文信息不足，按 pm-conventions §10.2 补读知识库（page-modules.md、database-schema.md）
4. 规划页面列表，标注核心字段和 TBD 字段

**PRD 模式**：
1. 读取需求文档，提取功能清单、流程图、需求详情、角色权限、数据模型
2. 读取 Baseline（如有）作为补充参考
3. 规划页面列表

**通用**：
- 按前端样式参考源优先级读取样式；存量改造额外读取目标 Vue 文件
- 规划页面列表（标注全新/存量改造/原型迭代），确认生成模式后开始生成

### Step 2：生成样式

`[Phase 1 · Step 2/4]`

进入本 Step 前，先读取样式模板、页面类型模板和生成规则（路径见"路径配置"）。

按 `templates/generation-rules.md` 中的规则判断生成方式（原型迭代 > 存量改造 > 全新功能），并按对应步骤执行。Vue 组件解析规则和降级策略同见该文件。

- **已有原型存在时**：从已有原型提取样式，仅追加新样式
- **首次生成时**：从样式模板获取完整模板，校验与项目实际值是否一致

> 原型使用原生 HTML/CSS 模拟 Element UI 组件的 class 命名，不引入 Element UI 库本身。

### Step 3：生成页面

`[Phase 1 · Step 3/4]`

#### 生成模式判定

**默认单文件模式**：所有页面合并为一个 HTML，CSS/JS 内联，多页面通过顶部导航栏切换。

**降级为多文件的条件**：超过 3 个独立功能页面且每页有复杂交互；页面间功能完全独立；用户明确要求。

**多文件模式**：导航入口 `{需求名}.html` + 子页面 `{页面功能名}.html` + 共享 `styles.css` + 可选 `scripts.js`

> 原型迭代时保持已有模式不变。

#### 页面生成规则

**通用规则**：完整页面布局（侧边栏、顶栏、内容区）、真实示例数据、表单字段与输入文档数据模型一致、基本交互效果（纯 JS）。

**单文件模式**：所有页面合并到一个 HTML 中，通过顶部导航栏切换 `page-view`。导航超过 5 个按钮时使用横向滚动或"更多"下拉。

**多文件模式**：每页独立 HTML，侧边栏用 `<a href="{页面名}.html">` 链接。超过 3 页时提取共享 `scripts.js`。

各页面类型结构模板和交互规范详见页面类型模板。

#### 导航首页

包含：需求名称和版本、页面列表（带缩略描述）、本次改动摘要、变更标记说明。

### Step 4：校验 + 输出总结

`[Phase 1 · Step 4/4]`

#### 生成后校验

- **单文件**：HTML 完整性 + page-view ID 与导航按钮匹配
- **多文件**：CSS/JS 引用路径 + 页面间链接检查

校验失败自动修复，仍未通过标注"需人工确认"。

#### 输出总结

告知：原型文件位置、生成模式和页面数、如何查看/分享/微调、样式来源、推断组件汇总（如有）、用户验收检查单。

#### 后续引导

**Baseline 模式**：

> ✅ 探索性原型已生成：`{文件路径}`
> 📋 下一步：请执行 `/pm-proto-review` 对原型进行交互评审，评审通过后再写 PRD。

**PRD 模式**：

> ✅ 精确原型已生成：`{文件路径}`（基于 PRD v{N}）
> 📋 如需调整，可直接描述修改内容，我会更新原型。

### 流程结束声明

## 生成原则

- **保真度优先于花哨**：字段完整、布局合理、交互逻辑正确
- **核心路径优先**：优先完善核心业务路径的交互展示，边缘功能可简化为占位
- **真实数据优于占位符**：使用基于输入文档数据模型的真实示例数据
- **产品语言优先**：原型中表单标签、表格列标题统一使用产品语言（用户可见的名称），不使用技术字段名
- **审计字段过滤**：系统自动生成的审计字段（创建人/时间、更新人/时间等）不在原型表单中展示，列表页按实际需求选择性展示
- **便携性优先**：默认单文件模式，一个 HTML 包含所有内容
- **纯 HTML/CSS/JS**：不依赖外部框架或 CDN，离线可用
- **中文命名优先**：原型 HTML 文件使用中文命名，CSS/JS 文件使用英文命名（`styles.css`、`scripts.js`）
- **组件一致性**：使用 Element UI class 命名体系
- **单文件控制**：单个 HTML 建议 ≤600 行；超过时自动触发多文件模式降级判断，但用户可选择保持单文件
