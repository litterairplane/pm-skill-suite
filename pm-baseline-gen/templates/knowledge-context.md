# 知识上下文文件输出规则与模板

> [适用范围] 仅 pm-baseline-gen Phase 3 使用。Phase 3 执行前读取本文件。

## 输出规则

在生成 Baseline **之后**，基于其功能架构补全知识上下文，输出 `{需求简称}-知识上下文.md`：

1. 从分析报告「已确认的知识库信息」章节提取全部内容
2. 整合 Phase 1-2 中从知识库补充验证的、分析报告中未包含的新信息
3. **按功能架构补全模块级信息**：
   遍历 Baseline 功能架构树中的每个模块（仅限 Baseline 中实际纳入的模块，
   排除在「方案决策摘要」中标记为"已排除"的内容），检查知识上下文中是否已包含
   该模块涉及的系统现状信息。如果缺失，按 pm-conventions templates/knowledge-base.md
   补读知识库并写入知识上下文。

   补全标准——按数据写入路径区分补全粒度：

   | 信息类别 | 补全条件 | 核心表（需求直接增删改） | 关联表（仅查询引用） |
   |---------|---------|---------|---------|
   | 数据表字段 | 模块涉及某张表 | 完整字段列表 | 主键 + 需求涉及字段 |
   | 页面布局信息 | 模块涉及改造已有页面（仅 involves_frontend=true 时适用） | 筛选条件、列表字段、操作按钮（仅记录按钮名称和触发动作类型：导航/弹窗/接口调用，不记录状态逻辑）、排序/分页 | — |
   | 状态/流程流转规则 | 模块涉及新增/修改状态或流程 | 所有状态、转换条件、触发动作 | — |
   | 枚举值列表 | 模块涉及使用/扩展某个枚举 | 枚举值 ≤ 20 个：完整值列表及含义；> 20 个：优先按需求涉及的分组完整列出该分组值，如无明确分组则列出需求涉及值 + 总数说明 | — |
   | 上下游关联 | 模块涉及修改已有功能 | 指**业务流程层面**的上下游（哪些功能会触发/被触发本模块），非数据库外键关联。优先从知识库 business-domains.md 获取；如知识库未记录则标注"上下游关联待开发确认" | — |

   **跨模块分类规则**：同一张表在不同模块中的分类**取最高级别**——任一模块直接增删改即按核心表标准记录完整字段列表。

   **不补全的情况**：
   - 纯新增功能（系统中不存在对应模块）→ 无现状可查，跳过
   - 分析报告「已确认的知识库信息」章节已包含且信息完整 → 不重复读取
   - 涉及页面信息但知识库中该页面记录不完整 → 标注信息缺失点，建议在 PRD 评审阶段由前端补充

4. 根据功能架构和核心规则内容，判断本需求是否涉及前端页面变更（`involves_frontend`），写入文件头部
5. 按知识上下文模板结构输出

## 知识上下文模板

```markdown
> 本文档为本需求相关的知识库信息摘要，由 pm-baseline-gen 自动生成。
> 后续 skill 优先从本文档获取知识库上下文，信息不足时再读知识库原文件（pm-conventions templates/knowledge-base.md）。
> 最后更新：{日期} by pm-baseline-gen
> involves_frontend: {true/false}

# 一、涉及服务与现状

| 服务 | 角色 | 涉及功能点 | 知识库路径 |
|------|------|-----------|-----------|

# 二、相关数据结构（如涉及）

## 2.x {表名/数据对象}
- 用途：{说明}
- 关键字段：{表格}

# 三、相关页面与菜单（如涉及前端）

| 页面 | 菜单路径 | 前端文件 | 布局类型 |
|------|---------|---------|---------|

# 四、现有功能逻辑

## 4.x {功能名}
- 当前行为：{描述}
- 来源：{knowledge 文件路径}
- 验证结论：{L1 验证结果}

# 五、枚举值与常量（如涉及）

| 枚举/常量 | 值 | 说明 | 来源 |
|----------|---|------|------|

# 六、接口与超时配置（如涉及）

{接口信息}

# 七、补充信息

> 后续 skill 回写的新增信息如找不到对应章节，统一追加到此章节。
```

## 注意事项

- 保留每条信息的「来源」或「知识库路径」字段，便于后续 skill 需要更多细节时定位原文件
- 仅包含分析报告「已确认的知识库信息」章节的事实性信息，不含候选方案、问题清单等非知识库内容
- 章节可按实际内容裁剪（不涉及前端则不输出第三章，不涉及枚举则不输出第五章）

## involves_frontend 判定标准

- 需要新增或修改**前端页面布局**（列表页、详情页、弹窗、表单等页面结构）→ `true`
- 仅涉及按钮/入口/操作触发但不涉及页面结构变更（如"导出 Excel"按钮）→ `false`
